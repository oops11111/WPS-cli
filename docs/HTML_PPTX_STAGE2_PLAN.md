# HTML to PPTX stage 2 animation verification plan

Base: `main` at `5279bd35a625d190895d9484057047ebe7e30cfe`. Depends on accepted stages 1A/1B. Scope is the three existing HTML→PPTX sources (`launch`, `training`, `quarterly`) and their CSS effects, slide transitions and speaker notes. Existing product animation mapping may change only for a reproducible, general defect. No static layout, unavailable `teaser.mp4`, fixtures, DOCX/XLSX or thresholds change. Merge target is `main`; the primary agent reviews the diff and merges only after all six CI jobs pass.

| Gate | Input and verification | Deliverable and acceptance | Stop condition |
| --- | --- | --- | --- |
| Source intent | Parse the three fixed HTML sources and CSS into slide, element, keyframe, duration, delay and `data-trigger`/`data-transition` inventory. Retain exact source hashes. | One machine-readable source-intent manifest covering 12 slides, 13 mapped effects, 12 transitions and 3 notes; unsupported span/hover/media warnings explicit. | Ambiguous selector or unsupported animation is recorded as unverified, never silently matched. |
| OOXML semantics | Inspect the exact Stage1A PPTX packages: `p:timing`, shape/paragraph target, preset class/subtype/direction, trigger grouping, effect order, delays, duration, `p:transition` and notes. Compare each to the source inventory. | Every applicable source item matched to a target with exact or justified semantic mapping; duplicate IDs, dangling targets, missing notes or mismatched timing fail. Existing package hashes and raw XML retained. | If a generic mapping defect is proven, repair only `html_slides.py` and add focused tests; otherwise no product change. |
| WPS acceptance | Open disposable copies in WPS Presentation 12.8.2.18913, inspect the COM object model for transition/effect/trigger/order/duration/notes, record opened file and process/version. | Machine-readable COM observations for all three decks. This proves WPS parsed properties; it does not prove screen motion. | COM unavailable or unsupported property is explicitly `unverified` with error evidence. |
| WPS visual playback | Start a fresh slideshow for each deck and observe initial/final state, manual click effects and slide progression; collect timestamped screenshots or equivalent visual evidence. Compare observed order and direction with source intent. | One new real-device playback record for 12 slides, including `training` click/after and exit/emphasis, `launch` fly/fade, `quarterly` table zoom, transitions and notes separately. Only directly observed behaviors pass. | Locked/inaccessible desktop, blocked automation or ambiguous frames => STOP; old 2026-10-22 playback.json is historical only. |
| Acceptance and PR | Run targeted slide/animation tests, Ruff/format/JS syntax, verify source/PPTX/renderer hashes and no unrelated file changes. | Stage2 report, raw manifest/screenshots, Conventional Commit, dedicated branch/PR. CI and device evidence are independent gates. | Do not claim animation high fidelity until both OOXML and actual playback gates pass. |
