# HTML to PPTX inline animation: stages 4–6

Base `main`: `0a65bb1f54f7ec3e788d9f4fb9af50a7800a4669`. Merge target: `main`. Acceptance sources: the user's renewed high-fidelity goal, the merged [delivery plan](HTML_PPTX_FIDELITY_DELIVERY_PLAN.md) and [Stage3 final report](HTML_PPTX_STAGE3_FINAL.md). The fixed launch/training/quarterly set remains the boundary. The unresolved visible video object and clean playback gates remain separate; this plan does not add media, alter fixtures or thresholds, or reopen DOCX/XLSX.

The [Open XML `TextElement` reference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.textelement) permits `p:charRg` inside animation target `p:txEl`; [Microsoft's animation example](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-animation) uses it for text within a shape. [Microsoft's implementation note](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/d0b4598c-f4e1-47ff-91b0-8fb5abb708f3) says PowerPoint requires `end > st` and `end <=` animated text length. This establishes a candidate OOXML representation, not WPS support or an offset convention for the current converter.
