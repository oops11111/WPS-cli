# Phase 6 计划：用户打开的文档

状态：**done**（2026-10-15）。三项出口标准都已达成，没有例外：G1 三个组件常规打开都能经 ROT 列出并导出；G2 五个已打开文档任务在一条命令里都是 3/3；G3 `v0.3.0` 已发布，Windows 上只装 wheel 通过。上机过程中发现并修复了两个产品缺陷：已打开文档的写入命令在真实 WPS 上总是被备份前的独占检查拒绝（0.2.0 里也有），演示选区替换读回方式有误。留下的缺口：P5-010（第二个 WPS 版本、干净机器）；已打开文档的写入如果校验失败，回滚会被 WPS 持有的文件挡住，应改为在 WPS 里撤销。计划于 2026-10-15 确认，五项决定均按默认建议。

## 目标

85 个工具里有 14 个处理“已经在 WPS 里打开的文档”：列出打开的文档、保存、导出，以及按选区替换、插入、删除文字。PRD v1.2 把这类操作作为主要场景：用户自己在 WPS 里打开文档，让 Agent 在里面改。

Phase 5 的实测发现，这个场景目前在 Writer 上用不了。用户双击 `.docx` 打开的 WPS 文字不注册 `kwps.Application`，`open-documents` 看不到它，所有已打开文档命令都会按“没有运行中的 Writer”处理（P5-011）。评测里唯一的已打开文档任务，是把打开命令改成 `/Automation`、再分 3 次单独跑才通过的。

Phase 6 要回答两个问题：

1. 用户用平常的方式打开的文档，三个组件的已打开文档命令都能用吗？用不了的组件，Agent 能不能拿到一个说清原因和办法的错误码，而不是“WPS 没在运行”？
2. Agent 能不能完成已打开文档上的写入：按选区改文字、保存？评测里一个这样的任务都还没有。

## 出口标准

每一条都要有可机器读取的记录（测试、结果 JSON 或提交到仓库的结果文档），只按实测结果判定。

| # | 出口标准 | 怎么算达成 |
| --- | --- | --- |
| G1 | 用户打开的文档，命令看得到，或者明确说看不到 | 在 Windows 上，分别用双击（系统默认的打开命令，不改注册表）打开 Writer、表格、演示文档。每个组件要满足下面两种情况之一：`open-documents` 列出该文档，并且 `export-open-document-text` 能导出它；或者命令返回专门的错误码，错误信息写明原因（比如“WPS 在运行，但没有注册自动化接口”）和用户能照着做的办法，不能报成没有运行中的 WPS。两种情况都要有离线测试（假 COM），Windows 结果记到仓库 |
| G2 | Agent 能在已打开的文档上写入 | 新增至少 4 个评测任务，覆盖 Writer 选区替换、Writer 选区插入、演示选区替换和 `save_open_document`。每个任务写明预期工具。需要 WPS 的已打开文档任务（新任务加上 `wps-open-document-export-text`）在 Windows 上用一条 `--repeat 3 --min-passes 2` 命令跑完，至少 2/3 通过，并且不改系统的打开命令 |
| G3 | 发布 0.3.0 | 按 `docs/RELEASING.md` 发布 `v0.3.0`，包含 G1 和 G2 的改动；在 Windows 的新虚拟环境里只装这个 wheel，`inspect-env` 和 safe 档回归都通过 |

## 已做的决定

2026-10-15 确认，均按默认建议：

| 决定 | 结论 | 依据 |
| --- | --- | --- |
| 找不到常规打开的 Writer 时怎么办 | 先查清楚（ROT 里登记了什么、能不能按文件路径 `GetObject` 拿到文档）。能附着就附着；不能附着就返回专门的错误码，不替用户重启 WPS | 现有原则是附着时不启动、不关闭用户的 WPS。用 `/Automation` 重新打开会丢掉用户的未保存改动 |
| 评测怎么准备“选区” | runner 在 Windows 上用 COM 选好一段文字，再交给 Agent；判定时检查文件内容 | 选区工具只改当前选区。让 Agent 自己选区，测的就是另一件事了；而且现在没有设置选区的工具 |
| runner 启动的 WPS 进程 | 只结束 runner 自己启动、并且已经没有其他文档的进程，按 PID 记录 | 让 `--repeat` 可以跑；不碰用户本来开着的 WPS |
| 是否新增工具 | 不新增，只改现有工具的附着方式、错误信息和说明 | 85 个工具的规模不变（P4-014 的决定），这一阶段要解决的是现有工具能不能用 |
| 第二个 WPS 版本 | 仍然不作为出口标准；P5-010 拿到条件时再做 | 同 Phase 5 |

## 建议顺序

1. 先做 P6-001 和 P6-002：后面的设计都取决于常规打开的 WPS 在 ROT 里登记了什么。
2. 在等 Windows 结果的时候，做不依赖它的本地任务：P6-005、P6-006、P6-007。
3. P6-003 依据 P6-002 的结果来做。
4. 第二次上机合并做 P6-004 和 P6-008。
5. 最后做 P6-009 和 P6-010。

## 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 常规打开的 Writer 在 ROT 里什么都没登记 | G1 只能用错误码那一种方式达成，Writer 上的已打开文档命令仍然用不了 | G1 本身就允许这个结果；README 写明怎么启动 WPS 才能用（比如快捷方式加 `/Automation`），并说明会丢什么 |
| 按文件路径 `GetObject` 在文档没打开时会启动 WPS 去打开它 | 违反“附着时不启动 WPS”的原则 | 先确认文档已在 ROT 里登记，再用这个路径取；诊断脚本只读 ROT，不调用 `GetObject(path)` 去碰没登记的文件 |
| 用 COM 设置选区在不同版本上行为不同 | G2 任务不稳定 | 选区只在 runner 的准备步骤里设置；设好后读回选区文字核对，不一致就把这次运行记为准备失败，不算 Agent 失败 |
| runner 误关用户的 WPS | 用户丢失工作 | 只关 runner 自己启动、按 PID 记录、并且没有其他文档的进程；手册要求上机前关掉所有 WPS 窗口 |
| 两次上机之间间隔长 | 阶段拖长 | 本地任务不等 Windows 结果；诊断脚本先做，第一次上机只跑它 |
