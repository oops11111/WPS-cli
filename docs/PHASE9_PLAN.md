# Phase 9 计划：Agent 选对工具、文本导出不丢字、上机不用手工清理

状态：**active**（2026-10-16 确认，五项决定均按默认建议）。

## 目标

Phase 8 让中文内容端到端可用，双击打开的工作簿也能关闭并恢复，0.5.0 已发布。Phase 8 的上机记录里还有三类问题，都不是出口标准，但每一类都会在用户或 Agent 手里再出现：

1. **Agent 对已打开的文档用了按文件的写入工具。** P8-008 第一轮，演示的插入和删除各有一次运行调用了 `presentation_replace`，得到 `DOCUMENT_HELD_OPEN` 后才改用选区工具，任务按 2/3 判通过。拒绝本身是对的（文件被 WPS 占用，不能改），但错误信息没告诉 Agent 该用哪个工具，Agent 只能自己猜。
2. **文本导出会丢字。** WPS 12.8 把 Writer 的文本导出按系统代码页（GBK）写出，`export-open-document-text` 在 0.5.0 里改为接受 GBK（#100），但 GBK 表示不了的字符（比如 `✅`、`𠮷`）在 WPS 写文件时就已经变成 `?`，事后接受也找不回来。当时没有记录 `export_method`，不知道是 `SaveAs2(…, 7)` 本身写成了 GBK，还是退到了纯文本格式 2。
3. **每次上机前都要手工关掉 WPS 恢复的文档。** runner 清理时用 `Stop-Process` 结束 WPS 进程；如果那时 WPS 里还开着文档，WPS 下次启动时当成异常退出，把它们恢复出来（Phase 7 的 `status.xlsx`、Phase 6 的 `deck.pptx`）。P8-007 能记录这些文档，但每轮上机前仍要你在 WPS 里手动关掉。

Phase 9 把这三件事做完，最后发布 0.6.0。

## 出口标准

每一条都要有可机器读取的记录（测试、结果 JSON 或提交到仓库的结果文档），只按实测结果判定。

| # | 出口标准 | 怎么算达成 |
| --- | --- | --- |
| J1 | Agent 对已打开的文档用选区工具 | 离线：每个按文件的写入工具（Writer、表格、演示的替换和写入类命令）在目标文档已在 WPS 里打开时，错误信息写明对应的已打开文档工具和参数怎么对应；这些工具的 MCP 说明写明不用于已在 WPS 里打开的文档；评测的每次运行记录 `wrong_tool_calls`（对已打开文档调用按文件写入工具的次数），`RESULTS.md` 显示。Windows：全部已打开文档任务（现有 15 个加 J2 的新任务）用一条 `--repeat 3 --min-passes 2` 命令跑完，每个至少 2/3，且所有运行的 `wrong_tool_calls` 合计为 0 |
| J2 | 文本导出不丢字 | `export-open-document-text` 对 Writer 和表格写出的文件是 Unicode（UTF-8 或带 BOM 的 UTF-16），GBK 以外的字符原样保留；结果里记录 `export_method` 和 `text_encoding`；每个组件有假 COM 测试。Windows：一个新评测任务导出含 GBK 以外字符（`✅`、`𠮷`）的已打开文档，在 J1 的那条命令里至少 2/3，且没有一次的 `text_encoding` 是 `gbk` |
| J3 | 上机不用手工清理 | runner 清理时先关掉它打开的文档，再让它启动的 WPS 正常退出（`Quit()`），只有退出失败时才结束进程，并在 `cleanup` 里写明是哪一种。Windows：上机前清理一次之后，J1 那条命令的每次运行 `documents_outside` 都为空，`cleanup` 里没有一次是在 WPS 还开着文档时结束进程 |
| J4 | 发布 0.6.0 | 按 `docs/RELEASING.md` 发布 `v0.6.0`，包含 J1、J2 的改动；用 `run_windows_check.py wheel` 在 Windows 上检查 wheel |

## 已做的决定

2026-10-16 确认，均按默认建议：

| 决定 | 结论 | 依据 |
| --- | --- | --- |
| Phase 9 做什么 | 上面三件事加发布 0.6.0 | 都来自 Phase 8 的实测记录，每件都有现成的评测或上机步骤可以验证 |
| 怎么让 Agent 选对工具 | 改错误信息和工具说明，并在评测里统计 `wrong_tool_calls` | 拒绝是对的，缺的是“该用哪个”；改信息不改行为 |
| 文本导出怎么保证 Unicode | 先在 WPS 写文件时指定 UTF-8 编码（`SaveAs2` 的 `Encoding` 参数）；WPS 不认时，由脚本经 COM 读出文档文字、自己按 UTF-8 写文件，并在 `export_method` 写明走的是哪条路 | 第一条保留 WPS 自己的文本排版（表格用制表符分隔）；第二条保证不丢字 |
| runner 怎么结束 WPS | 对它启动的 WPS 调 `Quit()`，失败才 `Stop-Process`；不改 WPS 的“恢复上次会话”设置 | 正常退出时 WPS 不会恢复文档；不该改用户的 WPS 设置 |
| 版本号和其余缺口 | 0.6.0（J2 改变了导出文件的编码，属于改变默认行为，按 `docs/RELEASING.md` 升次版本）；`0x800A01A8`、图表和图形撤回、第二个 WPS 版本都留在缺口里 | 前一个两次上机都没复现；后两个没有评测任务或条件 |

## 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| WPS 不认 `SaveAs2` 的 `Encoding` 参数 | J2 只能走自己写 UTF-8 的那条路，表格排版和 WPS 导出的不同 | 决定里已经给了这条后备；`export_method` 记录走的是哪条 |
| Agent 仍然先试按文件的工具 | J1 的 `wrong_tool_calls` 不为 0 | 先看是错误信息还是工具说明没起作用，再改；评测按次统计，能看出改了之后的变化 |
| `Quit()` 在有恢复实例或对话框时卡住 | 清理变慢或失败 | 设超时，超时后仍按原来的方式结束进程，并记录下来 |
| 上机轮次多 | 阶段拖长 | 本地任务先做完；J1、J2、J3 共用一次上机 |
