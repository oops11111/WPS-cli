# WPS AI Agent CLI 后续开发路线图

## 阶段目标

### Phase 0 技术调研与可行性验证

目标是在真实 Windows + WPS 环境下确认核心假设是否成立，产出可行性报告和版本矩阵。

交付物:

- WPS 版本、ProgID、COM 注册与可用性矩阵
- 最小 COM 原型: 启动、打开、保存副本、关闭
- 表格公式写入、真实计算、原始值与显示值核对样例
- ExportAsFixedFormat 和 SaveAs2 的实际可用性与损失记录
- HTML 视觉优先转换基线
- 风险清单和进入 Phase 1 的准入结论

### Phase 1 MVP CLI

目标是形成可被 Agent 稳定调用的最小可运行版本。

交付物:

- 公共能力: 能力查询、连接、打开、列出、保存副本、关闭
- 稳定 document_id、请求 ID、幂等保护、任务状态查询
- 修改前强制备份和基础恢复路径
- WPS 文字、表格、演示三组件核心读写
- 基础格式转换矩阵和批量报告
- dry-run 预览
- 结构化 JSON 输入输出、错误码、验证结果
- 单元测试、集成测试样例和端到端 Agent 流程测试

### Phase 2 Agent 可用版本

目标是从能用升级到好用且可规模化。

交付物:

- 常驻会话与多文档并行
- MCP 与 CLI 共用核心逻辑
- 长任务进度流、可中断设计、资源回收
- HTML 三模式: 视觉优先、可编辑优先、受控往返
- 结构化日志、执行轨迹、本地诊断命令
- 批量目录处理和逐文件状态报告

### Phase 3 生产就绪版本

目标是成为 Windows 上 WPS 自动化的可靠基础设施。

交付物:

- 跨组件转换和高级能力验证
- 更强备份恢复、事务边界和审计日志
- 自动化回归测试套件
- 真实 Agent 端到端评测流水线
- 生态扩展评估

### Phase 4 多环境与 Agent 工作流就绪（done）

目标是让这套工具在多个 WPS 版本、多个 Agent 客户端上可用，Agent 能安全完成真实的 WPS 写入任务，出错时可在 CLI 内恢复，并且可以发布。

交付物：

- Phase 3 遗留的三项 Windows 验证
- 至少两个 WPS 版本的兼容矩阵
- 覆盖 WPS 写入路径的 Agent 评测，每个任务多次运行并统计通过率
- 第二个 MCP 客户端验证（Codex CLI 或 Claude Desktop）
- 文档打开时需显式同意的"关闭后恢复"
- 发布流程：版本号、变更记录、wheel、干净机器安装验证

出口标准和任务拆分见 `docs/PHASE4_PLAN.md`。

### Phase 5 首个正式版本与覆盖扩展（done）

目标是让每个工具出错时 Agent 都能看到错误码，把 Agent 评测扩展到 4 个写入任务以外的常见工作，并发布一个不依赖仓库也能用的正式版本。

交付物：

- 覆盖 85 个工具的 MCP 失败契约测试，以及它找到的问题的修复
- 至少 6 个新的 Agent 评测任务，记录预期之外的工具调用
- 首个正式版本 0.2.0：GitHub Release、wheel 单独安装可跑 safe 档回归
- 全仓库格式统一并由 CI 检查

出口标准和任务拆分见 `docs/PHASE5_PLAN.md`。

### Phase 6 用户打开的文档（done）

目标是让已打开文档的命令能用在用户平常方式打开的文档上，做不到时明确告诉 Agent 原因和办法；证明 Agent 能在已打开的文档上写入；发布 0.3.0。

交付物：

- 查清常规打开的 WPS 在自动化接口上登记了什么，据此改附着方式或给出专门的错误码
- 至少 4 个已打开文档的写入评测任务，runner 能在 Windows 上连续多次跑这类任务
- `CELL_NOT_FOUND` 给出表格大小
- 版本 0.3.0 及其 Windows 安装检查

出口标准和任务拆分见 `docs/PHASE6_PLAN.md`。

### Phase 7 已打开文档的写入可撤回、全覆盖（done）

目标是已打开文档的写入失败时在 WPS 里撤回，而不是被挡住的文件回滚；在 Windows 上评测全部已打开文档写入命令；Windows 检查一条命令完成；发布 0.4.0。

交付物：

- 8 个已打开文档选区写入命令的 WPS 内撤回，以及在 Windows 上注入失败的验证
- 至少 5 个新评测任务，覆盖剩下的已打开文档写入命令
- 一条命令完成 Windows 检查并生成结果文件
- 版本 0.4.0 及其 Windows 安装检查

出口标准和任务拆分见 `docs/PHASE7_PLAN.md`。

### Phase 8 中文内容和常规打开的工作簿（done）

目标是中文内容端到端可用，用户双击打开的工作簿能被 CLI 关闭；先发布 0.4.1，最后发布 0.5.0。

交付物：

- 非 ASCII 文本经过的每条路径都有 GBK 区域设置下的测试，至少 4 个中文评测任务在 Windows 上通过
- `restore-backup --close-in-wps` 对双击打开的工作簿可用，或者返回说明原因的专门错误码
- 版本 0.4.1 和 0.5.0 及其 Windows 安装检查

出口标准和任务拆分见 `docs/PHASE8_PLAN.md`。

### Phase 9 Agent 选对工具、文本导出不丢字、上机不用手工清理（done）

目标是 Agent 对已打开的文档用选区工具，文本导出保留 GBK 以外的字符，Windows 上机不再需要手工关掉 WPS 恢复的文档；发布 0.6.0。

交付物：

- 按文件的写入工具在文档已打开时指出该用的选区工具，评测统计用错工具的次数
- 文本导出写 Unicode，一个含 GBK 以外字符的评测任务
- runner 让它启动的 WPS 正常退出
- 版本 0.6.0 及其 Windows 安装检查

出口标准和任务拆分见 `docs/PHASE9_PLAN.md`。

## 阶段准入规则

- 先验证，再实现。
- 每项能力必须有对应测试和可机器解析的结果。
- 兼容性、精度、成功率只基于实测记录。
- 修改操作没有备份和验证结果时不得进入可用功能集。
