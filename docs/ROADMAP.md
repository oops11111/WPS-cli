# WPS AI Agent CLI 路线图

本文件只写还没做的事，按现在 / 接下来 / 以后 / 不做四档排。Phase 0 到 14 的历史计划与报告保留在 docs/ 的 PHASE 文档与 git 历史里，不再回写本文件；每完成一项就从这里删掉，并记进 CHANGELOG。

状态基线：0.11.3（2026-11-09）。2026 年 11 月的代码审查结论见仓库外的审查记录，条目编号（S/U/T/A/C）在下面沿用。

## 现在（1.0 之前收口）

- 真机证据补课（T-02/T-03）：第二台机器与第二个 WPS 版本的验证；在 COMPATIBILITY_MATRIX 标注每条证据的版本与日期，过期证据降级为未验证；windows_check 结果必须归档原始 JSON 与 wheel 的 SHA-256，不只留 Markdown 勾选
- 发布通道打开（U-04）：release 流水线的 PyPI 步骤已就绪，置 `PUBLISH_TO_PYPI=true` 后正式走 PyPI 分发，安装文档随之更新
- 命名收敛（U-01）：产品名统一为 `wps-agent`——仓库改名、文档与包描述同步；`wps-ai-agent-cli` 作为包名保留一个大版本兼容（README 首屏的消歧说明已先行落地）
- C-04 图表的真机校准：`spreadsheet-chart-create` 经 WPS 的 ChartObjects().Add 与 SetSourceData 加图，离线读回已覆盖，还需在装 WPS 的 Windows 上把柱、条、线、饼各跑一次，确认 WPS 保存的图表部件能被读回
- 发版节奏（U-06）：改为每两周一个 minor，只修不加功能时走 patch；满足 RELEASING.md 的 1.0 条件（API 冻结、默认翻转完成、真机自托管 runner、两台机器乘两个版本签核）后发 1.0

## 接下来（能力补强，顺序即优先级）

- C-05 表格三件：spreadsheet-sort、条件格式、数据验证，各是一个同构操作
- C-06 文字三件：按文件插图、页面设置、样式预设（预设清单先定稿）

## 以后（先拿数据再立项）

- 驻留模式（C-10）：先按 T-09 给出冷启 PowerShell 与 COM 的实测基线，证明是瓶颈再做常驻进程
- 通用批处理（C-07）：JSON 命令数组一次执行，复用 MCP 适配层的参数映射
- 路径定位读取（C-08）：/sheet["Sheet1"]/cell["C12"] 风格的 get 语法，落到现有读取上
- 演示编辑加深（C-11）：增删幻灯片、占位符文本、按文件插图
- 内部结构（A-01/A-05/A-06/A-09）：拆分 open_documents.py（4,000 行级）为按组件的编排模块；PowerShell 脚本从字符串常量迁为包内 .ps1 资源并统一 ComSession；CLI 改注册表分发；变更命令收拢到统一门面。这些只在新能力或真机数据逼出需求时逐项立项，不做一次性大重构

## 不做（已决定的边界）

- 云端处理与账号体系：与本地、离线定位冲突
- HTML 转换继续扩范围（A-04 决定）：冻结在现有输入输出内，只修 docx 主路径保真与明确报错；pptx 保持 best-effort 并在 CONVERSION_MATRIX 如实标注，两个版本内不新增 HTML 方向
- 为命令数量扩命令面：先把已有命令的真机证据补齐
- 宏的任何执行路径：打开文档一律禁用宏（自第一批加固起），不提供绕过开关给 CLI 与 MCP
