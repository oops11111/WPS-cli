# HTML to PPTX fidelity and animation delivery plan

Baseline: `main` at `e6b7405b3602f4a0bf11ddf84d5442ce65c6c7d8` (2026-11-22). Merge target: `main`. Acceptance source: the user's request; the existing A-group cases and aspect definitions in `docs/PHASE13_PLAN.md`; `docs/CONVERSION_MATRIX.md`. No related open issue or PR was found at planning time. This plan does not reopen DOCX/XLSX or add a new HTML direction. The existing PPTX support remains best effort until evidence supports a stronger claim.

The fixed source set is `fixtures/html_complex/launch.html`, `fixtures/fidelity/training.html`, and `fixtures/fidelity/quarterly.html`, with the same modes as `scripts/fidelity_baselines.py`: editable, appearance, editable. The historical F2 gate in `docs/PHASE13_PLAN.md` is aggregate WPS SSIM >=0.90 with text, structure, formatting and animation at 100%; its rows record earlier individual scores of 0.92, 0.95 and 0.95. This project additionally checks every slide against the browser source at the same slide size with a >=0.90 target. Report historical aggregate and the stricter per-slide target separately; do not silently redefine F2. Animation acceptance separately verifies target shape or paragraph, effect class and direction, trigger, order, delay, duration, transition and playback behavior. A static export or OOXML-only inspection cannot establish playback.

Stage 1 update, based on `main` at `309954b71103893aaf4eaf94baaa9a501003b769`: the stage 0 audit revealed that `launch.html` has auto-height sections, while the WPS target is a full 16:9 slide. The current scorer resizes each full target page to the source section screenshot's short height. Its launch scores remain recorded historical outputs, but they do not establish same-canvas fidelity or a product layout defect. Before interpreting a >=0.90 per-slide target, stage 1A must produce a comparable full-slide source render and retain the old scores separately. Stage 1 is therefore a STOP diagnosis with no converter change.

Stage 1A measurement rule, based on `main` at `dd0d1eaa719f26c3b168507083340ca5645e282d`: each top-level HTML section is a slide. Keep the original DOM, CSS, section size and child layout; hide only the other slide sections without reflow, and translate the current section's top-left to the 1280×720 browser viewport origin. The body margin locates slides in the long HTML document and is excluded from an individual slide. Capture the complete viewport in the browser. Reject source sections that exceed the canvas, transform/fixed/sticky sections, visible direct body siblings/text outside slides or visible leakage from hidden slides. This normalized presentation view is not an original document scroll position. Keep legacy section-crop scores in separate fields. A high whole-slide SSIM cannot excuse a missing visible media object: record source-to-target media presence as a separate acceptance item.

Each stage has one dedicated branch, one Conventional Commit series and one PR. The same implementation agent prepares code, tests and PRs; the primary agent reviews diffs and evidence, tracks all required CI jobs and merges only after each is green. If `main` advances, rebase and regenerate evidence before acceptance. A stopped stage records evidence and leaves the product path unchanged.

The local test, CI and WPS device gates are independent. Missing browser, WPS, credentials or an external service does not relax a gate. Report its concrete probe output, preserve the stage branch and avoid expanding the scope to unrelated formats.
If stage 0 finds no reproducible static or animation defect, skip the corresponding implementation stage with explicit evidence; do not create a nominal product PR.
