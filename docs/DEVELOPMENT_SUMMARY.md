## 7. Phase 13：高保真格式互转

### 7.1 目标

在 HTML 和 WPS 的三种格式（文字 docx、表格 xlsx、演示 pptx）之间双向转换，转换结果在 WPS 里打开的样子和原文件一致，并且仍然可以编辑。“一致”用可测量的指标判定，不靠人工看。

现在的位置：HTML → Office 已经保留语义、行内格式、合并单元格、数字格式、动画和切换（P12-013），但字体、字号、颜色以外的 CSS、版面位置、背景、边框、列宽都不转换；Office → HTML 只有经 WPS 另存的 HTML（WPS 自己的格式，不干净）和 docx 的受控往返（`html-export`、owned HTML v1）。

### 7.2 转换方向

| 方向 | 现在 | Phase 13 要做到 |
| --- | --- | --- |
| HTML → docx | 语义、行内格式、合并单元格、图片 | CSS 盒模型的主要属性：字体、字号、行距、段前段后、对齐、缩进、颜色、背景色、边框、表格列宽和单元格底纹、图片尺寸、分页 |
| HTML → xlsx | 合并单元格、数字格式、日期 | 单元格字体、颜色、底纹、边框、对齐、列宽、行高、冻结表头；（D3 定了的话）公式 |
| HTML → pptx | 标题、正文、表格、图片、备注、进入动画、切换 | 按 CSS 位置和尺寸摆放元素（绝对定位、flex/grid 的结果）；背景色和背景图；字体字号颜色；退出和强调动画；动画顺序（同时/之后） |
| docx → HTML | WPS 另存 HTML；owned HTML v1 往返 | 干净的语义 HTML + 内联样式，保留上面 HTML → docx 的全部属性，可以再转回 docx 不丢东西 |
| xlsx → HTML | WPS 另存 HTML | 每个工作表一个表格，合并单元格、数字的显示值、样式 |
| pptx → HTML | WPS 另存 HTML | 每页一个 section，元素按位置绝对定位，动画转回 CSS `@keyframes`，切换转回 `data-transition` |
| Office → PDF | WPS 导出（`convert-smoke`、`export-open-document-pdf`） | 不变，作为“WPS 里看到的样子”的基准 |

### 7.3 怎么判定“高保真”

为每个方向建一个保真度检查，结果写进转换的返回值和评测记录：

| 检查 | 方法 | 建议门槛 |
| --- | --- | --- |
| 文字 | 源和结果的全部文字逐段比较 | 100% |
| 结构 | 标题层级、列表层级、表格行列和合并、页数或幻灯片数 | 100% |
| 格式 | 每段文字的粗细、斜体、下划线、颜色、字号、字体逐项比较 | 100%（不支持的属性列入警告，不计入） |
| 版面 | 源 HTML 用浏览器渲染成图，结果用 WPS 导出 PDF 再渲染成图，逐页比较结构相似度（SSIM） | ≥ 0.90 |
| 往返 | HTML → Office → HTML，再比较一次上面四项 | 与单程相同 |
| 动画 | pptx 的动画数量、类型、目标、延迟、顺序 | 100% |

版面检查在 Linux 上可以先用 LibreOffice 代替 WPS 跑（CI 能跑），Windows 上用 WPS 跑一次作为正式结果。

### 7.7 风险

| 风险 | 缓解 |
| --- | --- |
| CSS 的版面模型（流式、flex、grid）和 Office 的不对应 | 用浏览器算出每个元素的位置和尺寸（已有 Playwright），按计算结果摆放，而不是自己解释 CSS |
| WPS 和 LibreOffice 渲染不同，CI 通过但 WPS 上不一致 | 门槛以 WPS 结果为准，LibreOffice 只做回归 |
| 高保真和可编辑冲突（比如绝对定位的段落） | 按 D9 默认可编辑优先，外观优先作为选项 |
| 版面相似度对字体敏感 | 输入和比较都固定字体；缺字体时在结果里报告 |
