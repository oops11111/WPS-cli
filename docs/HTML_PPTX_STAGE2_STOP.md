## WPS device gate: partial acceptance, visual STOP

The first [WPS probe record](../artifacts/html-pptx-stage2-20261122/wps_probe.json) shows the installed `wpp.exe` file version 12.8.2.18913. `@oai/sky.list_apps()` returned no running WPS Presentation window. A subsequent `sky.launch_app` call never returned for about 1409 seconds and was interrupted; a later process check returned `NO_WPP_PROCESS`. This path yielded no WPS evidence.

The bounded fallback used the repository's previously recorded direct `wpp.exe "deck.pptx"` command on disposable copies. The [training launch log](../artifacts/html-pptx-stage2-20261122/training_direct_launch.json) records that the first attempt to hash its open copy hit WPS's file lock; launch and quarterly copies were hashed *before* opening. The [ROT diagnostic](../artifacts/html-pptx-stage2-20261122/direct_launch_com_diagnostic.json) found WPS PID 72356, the training copy's window title and exact file moniker, and `kwpp.Application` active with HRESULT 0. The three [COM timeline records](../artifacts/html-pptx-stage2-20261122/training_com.json) (`launch_com.json`, `quarterly_com.json` alongside it) each matched one loaded copy and reported 12 slides in total with effect counts `2/3/0/0/1/0`, `1/3/2`, `0/1/0`. WPS returned effect type, shape name, trigger type, delay, duration and transition enum for each effect/slide. The training click effect reads TriggerType 1, followed by an effect with 0.6000000 s delay; emphasis and exit durations read 1 s and 0.5 s. These observations establish that WPS accepted and exposed the package's animation properties. COM notes shape counts are present, while note text is confirmed only in OOXML.

The [training slideshow record](../artifacts/html-pptx-stage2-20261122/training-playback/playback.json) shows successful `Run`, `GotoSlide(2)`, `Next`, `GotoSlide(3)` and `Exit` calls, with observed slide indices 1→2→3. The direct screen captures show changing WPS frames, but a pre-existing `python.exe - 应用程序错误` dialog overlays them. That dialog already appeared in the first `sky.list_apps()` inventory, before this fallback. A window-targeted [PrintWindow attempt](../artifacts/html-pptx-stage2-20261122/training-window-capture/playback.json) returned false for all eight frames (WPS slideshow COM `HWND` was 0) and produced black images; one representative black frame is retained while the record preserves all eight capture outcomes. Neither capture path supplies clean evidence of full screen motion, timing and transitions. The historical `scripts/windows_check/results/20261022T150940Z-c149caf-fidelity/playback.json` remains historical only.

**Stage 2 remains STOP**, not animation high-fidelity acceptance. WPS property acceptance and training page advancement are evidenced; clean visual motion/display, direction, trigger timing and slide transitions across all three decks remain unverified. The three original PPTX SHA-256 values were rechecked unchanged after the disposable WPS copies and the sole WPS process started by this probe were closed. A later device run needs clean, timestamped screen observations without the unrelated modal. The final project gate still fails independently on the missing visible video control.
