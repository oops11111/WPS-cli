Stage 5 is **SKIP/STOP**, satisfying the plan's stop condition rather than its implementation acceptance criteria. The existing whole-paragraph animation warning remains accurate. This decision uses the merged Stage4 [candidate manifest](../artifacts/html-pptx-inline-stage4-20261122/candidate_manifest.json), [WPS COM control](../artifacts/html-pptx-inline-stage4-20261122/wps_com_final.json) and [static report](../artifacts/html-pptx-inline-stage4-20261122/candidate-static/static_report.json); it adds no duplicate artifacts.

To unlock a generic implementation stage, first demonstrate a reproducible mapping from DOM inline-node boundaries through collapsed text runs to PPTX character offsets for Chinese, non-BMP text, whitespace, repeated text and nested inline formatting. Then obtain a bounded, unobstructed WPS slideshow recording in which the unchanged prefix remains visible and only the target span animates with the expected delay/duration. Validate the resulting mapping against the fixed 12-page static and semantic baseline before proposing converter code.

Stage 6 remains a separate final reacceptance gate: it needs a fresh exact-main three-deck run and clean animation screen evidence. Overall HTML→PPTX support stays `best-effort`.
